### C1. SPA 兜底路由存在路径穿越，可读取磁盘上任意文件【已复现】

`apps/fire-sight/src/fire_sight/api/app.py:81-89`

```python
def spa(full_path: str) -> FileResponse:
    if full_path.startswith("api/"):
        raise HTTPException(status_code=404)
    candidate = WEB_DIST / full_path
    if full_path and candidate.is_file():
        return FileResponse(candidate)
    return FileResponse(WEB_DIST / "index.html")
```

`full_path` 未经任何校验就参与 `Path.__truediv__`，`..` 直接生效。`WEB_DIST` 位于仓库根下 3 层（`apps/web/dist`），因此逃逸需要 3 个 `..`。

**实测**（直接驱动 raw ASGI app，绕过 TestClient 的路径归一化）：

| 请求路径 | 结果 |
| --- | --- |
| `/../pyproject.toml` | 200，`text/html`，474 B（`index.html`，落空） |
| `/../../pyproject.toml` | 200，`text/html`，474 B（落空） |
| `/../../../pyproject.toml` | **200，`application/octet-stream`，2159 B —— 真实文件内容** |
| `/../../../AGENTS.md` | **200，`text/markdown`，5293 B，正文 `# AGENTS.md …`** |

子代理 `84dd07d4` 用真实 uvicorn + 原始 socket 进一步确认逃逸范围是 **E:\ 往下任意已存在文件**，包括仓库之外的 `E:\写字板.md` 与一个 3.6 MB 的 `E:\火焰视频.mp4`（响应 `200 video/mp4, 3686837 bytes`）。

> **纠正我此前的一个错误结论。** 本会话早期我用 `/../pyproject.toml`、`/../../pyproject.toml` 探过一次，得到 200 + `index.html`，就断定「Starlette 拒绝/归一化了逃逸路径，无可复现漏洞」。那个结论是**错的**：我的 payload 差一层 `..`，`WEB_DIST / ".." / ".."` 指向 `apps/pyproject.toml`（不存在）→ `candidate.is_file()` 为假 → 落回 `index.html`。我把「文件不存在」误读成了「逃逸被拦截」。差一层 `..` 就是一次假阴性，教训是负结果必须用**已知存在的目标**验证，而不是看到非报错响应就收工。

**缓解**：`cli.py:13` 默认 `--host 127.0.0.1`，且 `--host` 是用户可传参数，一旦监听 `0.0.0.0` 即为任意文件读取。无鉴权是明示的设计取舍（`app.py:34` 注释），因此这里不存在「先登录」这道额外防线。

**修**：

```python
resolved = (WEB_DIST / full_path).resolve()
root = WEB_DIST.resolve()
if full_path and resolved.is_file() and root in resolved.parents:
    return FileResponse(resolved)
```

（注意：`Path.resolve()` 后的包含性判断必须与 `apps/fire-sight/src/fire_sight/api/routers/events.py:188-223` 的 `get_clip` 采用同一写法——那里已经做对了，`events_root in resolved.parents`。）

### R3. `monitor` 的 MJPEG 流用同步无限生成器，每个停滞的观看者钉死一个 anyio 线程池 worker【已复现】

`apps/fire-sight/src/fire_sight/api/routers/monitor.py:110-128`

```python
def _mjpeg() -> Iterator[bytes]:
    while True:
        jpeg = MONITOR.latest_jpeg()
        if jpeg is None or jpeg == last:
            time.sleep(IDLE_SLEEP_SEC)     # 同步阻塞
            continue
```

我核对了 starlette 的 `StreamingResponse.__init__`：非 `AsyncIterable` 一律包成 `iterate_in_threadpool(content)`，而后者是 `await anyio.to_thread.run_sync(_next, as_iterator)`。`while True` 在源断线时永不返回 → 该 worker 永不释放。anyio 默认线程池约 40 个 token，且**与所有其他同步端点共享** → 几个停滞的观看者就能让整个 API 饿死。

**修**：改成 `async def _mjpeg()` + `await asyncio.sleep(...)` + `jpeg = await run_in_threadpool(MONITOR.latest_jpeg)`；或限制并发流数/在 N 次空转后退出。

### R12. 可视化的热路径按「每个检测」而非「每帧」付费【已复现，含性能实测】

### 架构类

- **没有单一的「文件系统边界」所有者。** C1 / C2 / C3 / R20 是同一个缺陷的四个面：用户可控的路径片段被交给 `Path.__truediv__`，而 Windows 上绝对路径输入会**静默替换**基路径。一个 `safe_join(root, component)` 可以帮助全避免其中两个 Critical。
