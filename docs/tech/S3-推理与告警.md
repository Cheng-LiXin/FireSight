# S3 技术设计 —— 推理与告警

## 模块边界

| 模块 | 职责 |
|---|---|
| frame_source | 多源读帧 |
| visualization | 中文绘制 |
| fire_sight.scene | 多帧确认/冷却 |
| fire_sight.alerting | 事件库/片段/TTS |
| inference | 薄编排 |

## 默认
confirm_frames=3, cooldown=30s, conf=0.25
clip_before=30s, clip_after=30s（片段保留告警前后各 30 秒）
事件库 data/events/events.db

## 片段留存
- 环形缓冲按「秒 × fps」定容，内部存 JPEG 压缩帧——30s × 30fps ≈ 900 帧，
  存原始 BGR 会到 GB 级，压着放是几十 MB。
- 告警当帧事件先入库（片段路径为空），后段攒满再落盘并回填 `clip_path`：
  中途断电丢的最多是一段没写完的片子，不会丢事件本身。
- 后段落盘在后台单线程写（千帧 VP9 编码比读帧慢一个数量级），主循环继续推理。
- 源提前结束时尾巴截到现有长度照写：短片段好过没片段。
