# S5 前端架构 —— FastAPI + Vue 控制台

> 阶段：S5 · 状态：进行中
> 接口契约见 [`../api/REST-API.md`](../api/REST-API.md)；阶段背景见 [`../ROADMAP.md`](../ROADMAP.md)

---

## 一、为什么重做

S4 阶段的 Streamlit 界面已归档。原因不在「不好看」，而在**交互模型不匹配**：

| 需求 | Streamlit 的问题 |
|---|---|
| 训练实时曲线 | 页面脚本从上到下重跑，无法维持长连接推送 |
| 大文件上传 + 预览 | 每次交互整页重跑，上传状态易丢失 |
| 精细的交互反馈 | 组件受限于框架封装，难以定制 |

因此改为标准的**前后端分离**：后端提供 REST，前端是一个真正的单页应用。

## 二、架构

```
浏览器
  │  /api/*
  ▼
FastAPI (fire_sight.api)
  ├── routers/        HTTP 契约：参数校验 + 序列化，不碰 SQL / YOLO
  ├── deps.py         工作区路径、事件库位置、GPU 互斥锁
  └── 静态托管        生产模式下把 apps/web/dist 挂在根路径
        │
        ▼
fire_sight.services      数据服务层（EventService / StatsService / InferService）
        │
        ▼
引擎：fire_sight_platform + fire_sight.scene / alerting + frame_source / visualization
```

**分层约束**：路由只做参数校验与序列化。任何 SQL 或 YOLO 调用都必须落在服务层之下，
以便界面更换时业务逻辑零改动——S4 换到 S5 时服务层几乎原样复用，正是这条约束的收益。

### 为什么是单体而不是 Node + Python 双服务

推理需要常驻的 PyTorch 进程（冷启动约 5–10 秒）。若让 Node 每请求 spawn 一次 Python，
上传识别会有十秒级延迟，交互上不可接受。

若 Node 只做代理，则它不承担任何真实职责，白白多一层部署复杂度。
故最终由 FastAPI 同时承担 API 与静态托管，Node 仅作为前端构建工具链。

## 三、GPU 资源互斥

8GB 显存下训练与推理无法并行，不处理就是演示现场 CUDA 溢出。

`deps.GpuLock` 提供全局互斥：非阻塞获取失败时**不排队**，直接返回占用者信息，
前端据此提示「训练进行中，可排队」而不是弹一个看不懂的 CUDA 错误。

```python
lock.acquire("train")     # 成功返回 True
lock.acquire("infer")     # 失败返回 False，不阻塞
lock.status()             # {"holder": "train", "waiting": [], "busy": True}
```

## 四、视觉方向：热成像取景

从题材本身长出视觉语言，而不是套用「深色大屏 + 荧光强调」的默认样式。

### 核心机制

热成像仪里，**冷物体呈饱和青蓝，热物体呈橙黄**。据此建立双色标：

| 编码什么 | 怎么编码 |
|---|---|
| **类别** | 决定色相家族 —— 烟雾走冷端，明火走热端 |
| **置信度** | 决定家族内的明度 |

这样任取一个色值都能唯一反推出「类别 + 置信度」，两个变量不会互相污染。

> **一次修正**：最初的设计原则是「除严重度外全部低饱和暖灰」，
> 于是把烟雾色定为 `#6E8A99`。配色校验器判定其彩度 0.039 低于下限 0.10，
> 报「reads gray」——它读起来是灰色，无法承担类别标识。
> 复查后确认是**原则本身错了**：真实热成像的冷端本就是饱和的，
> 把冷端做成灰等于让数据色退化成了界面 chrome。

### 令牌

```
基底    soot #17130E   ash #221C15   cinder #332A20
文字    bone #E9E1D4   dross #8C8172
对照    cool #5B7C8D                    ← 无目标 / 正常态
烟雾    冷端 #0A3E4E → #007E9C → #00A3C4 → #86DCEE
明火    热端 #7A1F1F → #D14A17 → #FF9A3C → #FFE9A8
```

类别槽位 `#00A3C4` / `#D14A17` 经色觉障碍模拟校验，在面板底色 `#221C15` 下六项全过：
明度带、彩度下限、CVD 分离（deutan ΔE 21.1）、常视觉分离（ΔE 30.8）、对比度。

> **改动这两个值必须重跑校验器**，不要凭眼睛判断。

### 三种容器

刻意不做「等权卡片墙」——同一个圆角盒子反复用会抹平信息层级：

| 容器 | 用途 | 形状语言 |
|---|---|---|
| `.fs-viewfinder` | 被观察对象（图像、曲线） | 带四角框标，全局唯一的记忆点 |
| `.fs-readout` | 仪表读数 | 无边框，只靠顶部分隔线与等宽数字成节奏 |
| `.fs-ledger` | 密集列表 | 表头 + 细线行，可排序 |

### 字体

- **Noto Sans SC / 系统 CJK** —— 承载中文与界面文案，层级靠字重拉开，不下载数 MB 字库
- **IBM Plex Mono** —— **只给数字**，且**凡是需要纵向对齐的数字都给**

关于等宽字体：它常被视作「AI 生成页面」的痕迹之一。这里使用它的理由是**仪表读数语义**——
数值需要对齐小数点、实时跳动时字宽不能抖。约束是只给数字、不给标签和正文。

反过来，**大号独立数字不用等宽**：等宽会让 `121` 在大字号下显得松散。
故风险尺读数用比例字形，读数条与表格用等宽。

## 五、图表规范

后端返回聚合数据，前端负责呈现。两条硬约束：

### 1. 绝不做双 Y 轴

「告警次数」与「平均置信度」量纲不同。放在同一张图上做双轴，
两个刻度的对齐关系是任意的，会**凭空造出数据里没有的相关性**。

改为两张共用 X 轴的小倍数图：上图看次数，下图看置信度。

### 2. 时间序列必须连续

`/api/overview` 的 `daily` 恒定返回 `days` 项，无告警的日子补 0。

若只返回有数据的日期，坐标轴会把「空窗」画成正常间隔——那等于对读者说谎。

但**补 0 只适用于计数**。平均置信度在无样本时是**未定义**而非 0，
前端对其做断点处理；若填 0，折线会砸到谷底，读起来像「模型置信度为零」。

### 3. 其他

- 类别颜色按固定槽位分配，不随筛选后的排名变化，也不按数值深浅着色
- 网格线用实线细线（虚线会被误读成「阈值」或「预测」）
- 两个及以上序列必须有图例；单序列不要图例，标题即命名
- 不做两段式饼图，数字本身就是答案

## 六、前端结构

```
apps/web/src/
├── api/
│   ├── types.ts        与后端 schemas.py 一一对应的类型
│   └── client.ts       fetch 封装，统一错误提示
├── charts/
│   ├── palette.ts      镜像 tokens.css（canvas 读不到 CSS 变量）
│   └── options.ts      ECharts 配置构造函数（纯函数）
├── components/
│   ├── RiskRuler.vue   风险尺：全局记忆点
│   ├── EChart.vue      图表容器，ResizeObserver 自适应
│   └── StatTile.vue    KPI 读数
├── stores/console.ts   系统状态与仪表盘数据的共享状态
├── styles/
│   ├── tokens.css      设计令牌
│   └── base.css        基底与三种容器
└── views/
    ├── DashboardView.vue
    └── PendingView.vue 未建模块的占位
```

**`api/types.ts` 与后端 `schemas.py` 必须同步修改。** 响应字段改名属破坏性变更。

### 画布与 CSS 变量的重复

ECharts 走 canvas，读不到 CSS 变量，因此 `charts/palette.ts` 必须镜像 `tokens.css` 的数值。

这是**必要且已知的重复**：改任一侧都要同步另一侧，并重跑配色校验器。文件内已标注。

## 七、无障碍与降级

| 项 | 做法 |
|---|---|
| 键盘焦点 | `:focus-visible` 用实线描边，不用光晕 |
| 降级动效 | 全局响应 `prefers-reduced-motion`，一并关闭过渡与动画 |
| 色觉障碍 | 类别配色经 deutan / protan 模拟校验，分离度 ΔE 21.1 |
| 对比度 | 所有文本与图表标记对底色 ≥ 3:1 |
| 空态 | 给出下一步动作（如「去做一次识别检测」），不是一句「暂无数据」 |
