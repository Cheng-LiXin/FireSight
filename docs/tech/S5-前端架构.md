# S5 前端架构 —— FastAPI + Vue 控制台

> 阶段：S5 · 状态：进行中
> 接口契约见 [`../api/REST-API.md`](../api/REST-API.md)；阶段背景见 [`../ROADMAP.md`](../ROADMAP.md)

---

## 一、为什么重做

S4 阶段的 Streamlit 界面已归档。原因不在「不好看」，而在**交互模型不匹配**：

| 需求 | Streamlit 的问题 |
|---|---|
| 训练实时曲线 | 页面脚本从上到下重跑，无法维持长连接推送 |
| 大文件上传 + 预览 | 每次交互整页重跑，上传状态易丢失 |
| 精细的交互反馈 | 组件受限于框架封装，难以定制 |

因此改为标准的**前后端分离**：后端提供 REST，前端是一个真正的单页应用。

## 二、架构

```
浏览器
  │  /api/*
  ▼
FastAPI (fire_sight.api)
  ├── routers/        HTTP 契约：参数校验 + 序列化，不碰 SQL / YOLO
  ├── deps.py         工作区路径、事件库位置、GPU 互斥锁
  └── 静态托管        生产模式下把 apps/web/dist 挂在根路径
        │
        ▼
fire_sight.services      数据服务层（EventService / StatsService / InferService）
        │
        ▼
引擎：fire_sight_platform + fire_sight.scene / alerting + frame_source / visualization
```

**分层约束**：路由只做参数校验与序列化。任何 SQL 或 YOLO 调用都必须落在服务层之下，
以便界面更换时业务逻辑零改动——S4 换到 S5 时服务层几乎原样复用，正是这条约束的收益。

### 为什么是单体而不是 Node + Python 双服务

推理需要常驻的 PyTorch 进程（冷启动约 5–10 秒）。若让 Node 每请求 spawn 一次 Python，
上传识别会有十秒级延迟，交互上不可接受。

若 Node 只做代理，则它不承担任何真实职责，白白多一层部署复杂度。
故最终由 FastAPI 同时承担 API 与静态托管，Node 仅作为前端构建工具链。

## 三、GPU 资源互斥

8GB 显存下训练与推理无法并行，不处理就是演示现场 CUDA 溢出。

`deps.GpuLock` 提供全局互斥：非阻塞获取失败时**不排队**，直接返回占用者信息，
前端据此提示「训练进行中，可排队」而不是弹一个看不懂的 CUDA 错误。

```python
lock.acquire("train")     # 成功返回 True
lock.acquire("infer")     # 失败返回 False，不阻塞
lock.status()             # {"holder": "train", "waiting": [], "busy": True}
```

## 四、视觉方向：现代简约 · 灰白黑

界面本身**无彩**，彩色额度只留一个给告警。这不是「素」，是刻意的分配：
彩色越稀缺，出现时越被看见——而这个产品的核心信息只有一个，就是「有没有火」。

### 核心机制

| 编码什么 | 怎么编码 |
|---|---|
| **告警与否** | 是否出现 `--alarm`（`#D14A17`）。全界面唯一允许的彩色 |
| **类别** | 明度：烟雾 `#1F2937` 深石板灰；明火就是那唯一的告警红 |
| **严重程度** | 风险尺前三档单色递深，只有最高档转告警红 |

配色不是凭观感挑的。度量口径：`ΔE = 100 × ‖OKLab(a) − OKLab(b)‖`，CVD 模拟用
Machado 2009 severity 1.0 矩阵。（原 `validate_palette.js` 已从开发机丢失；现版本是
按它记录的两组已知值反推、并自检复现的实现，见 devlog。）

白底实测（面板 `#FFFFFF`）：

| 用途 | 取值 | 对比度 | 常视觉 ΔE | deutan | protan |
|---|---|---|---|---|---|
| 类别：烟 / 火 | `#1F2937` / `#D14A17` | 14.68 / 4.47 | 37.2 | 36.3 | 25.1 |
| 训练曲线 4 色 | `#236EC2` `#B07B23` `#941C84` `#0B9D22` | 3.58–7.61 | 相邻最差 28.1 | 21.8 | 25.0 |

> **烟色不要改浅。** 曾用 `#6B7280`：它与 `#D14A17` 的明度几乎相同（0.551 vs 0.589），
> 而灰与红在红绿色盲下主要靠**明度**分离，protan ΔE 因此掉到 13.4——比原来在暗底上
> 验证过的 21.1 还差。压到 `#1F2937` 后三条通道全部优于基线。

> **训练曲线不能只用灰阶。** 实测在 `#FFFFFF` 上对比度 ≥3:1 的灰只有 5 档，相邻
> ΔE 掉到 6.8（要 ≥13 才算可区分）——「要够对比就得够深，够深了彼此就分不开」。
> 四条指标线因此保留彩色，但**沿用原 4 色板的色相**、只为白底重调明度彩度，
> 相邻最差 deutan ΔE 反而从 13.0 提到 21.8。

### 令牌

A 版落地后令牌名只剩一组，旧名（`soot` / `ash` / `bone` / `dross` / `cinder` /
`accent` / `fs-*` / `sp-*` / `radius-*` / `shadow-*` 等）已全部删除。留着别名
等于把「哪种才是正式名」这个问题永远留在每个改代码的人面前。

```
基底    canvas #EEF0F3   surface #FFFFFF   surface-sunk #F6F7F9
        line #DFE3E8   line-strong #C9CFD7   line-faint #ECEFF3
文字    ink #0D1117   ink-body #2F3742   ink-mute #6B7684   ink-faint #8A93A0
交互    signal #1F6FEB  signal-deep #1A5FD0  signal-soft #EEF4FD
告警    alarm #D1440D                      ← 全界面唯一的彩色额度
类别    cls-fire = alarm   cls-smoke #2F3742（中性深灰，不可用绿）
```

烟雾为什么必须中性深灰：红绿色盲下主要靠明度区分，原深石板灰与告警红的
OKLab ΔE 有实测 25.1 的余量；一旦把烟雾改成浅灰或绿，明度档被吃掉，类别区分
就只剩色相——恰好落在最看不见的那一类人身上。

字号跨度也是令牌：`t-micro .6875rem` → `t-body .875rem` → `t-read 2.25rem`
→ `t-hero 3.5rem`，中间不留过渡档。读数能当图形用，靠的就是这段空白。

**只做浅色。** `index.html` 不再挂 `class="dark"`，Element Plus 的
`theme-chalk/dark/css-vars.css` 不再引入，令牌覆盖从 `html.dark` 移到 `:root`。

### 容器

刻意不做「等权卡片墙」——同一个圆角盒子反复用会抹平信息层级：

| 容器 | 用途 | 形状语言 |
|---|---|---|
| `.readout` / `.readouts` | 读数与 KPI | 白底 + 1px 线 + `--r-lg` + `--lift-1`；hover 上抬 3px |
| `.panel` | 通用承载体 | 同上；`.panel__head` 放标题与右侧读数条 |
| `.tray` | 一排要你去操作的控件（参数栏、筛选栏） | 与 `.panel` 同底同圆角，但装的是输入 |
| `.sheet` / `.sheet--flush` | 表格 | 发丝横线、无竖线；`.num` 右对齐 |
| `.head` / `.btn` / `.pick` / `.chip` / `.dot` | 页头、按钮、互斥胶囊组、状态胶囊、类别点 | 全圆角（`--r-pill`） |
| `.fs-ledger` | 密集表格 | 表头 + 发丝横线；保留 `th.is-num` / `td.is-num` 右对齐契约 |
| `.fs-scroll` | 宽表格的横向滚动边界 | 无配方，只加一个 `overflow-x: auto` |

`.fs-ledger` 与 `.fs-scroll` 是旧版留下、至今仍在用的两件：前者是密集表格，
数字右对齐这条契约有 e2e 断言，不能改名；后者防止一张宽表把整页撑宽。
其余旧容器（`.fs-viewfinder` / `.fs-readout` / `.fs-tray` / `.fs-block` /
`.fs-btn-primary` / `.field`）随八页改完已退役。

`.tray` 与 `.panel` 的差别只有一个：里面装的是**你要填的东西**还是
**已经测出来的结果**。这个差别靠布局位置说话，不靠换个颜色。

### 外壳：顶栏胶囊导航

导航在顶栏，是一组胶囊；分两组——「值班总览 / 告警事件 / 识别检测 / 实时监控」
是值守链路，「模型库 / 训练中心 / 分析报告」是资产链路。两组之间只留一段空白，
不画竖线也不换底色：分隔线会让八枚胶囊看起来像两组按钮，空白只是节奏。

激活态是**冷色实心**（`--signal` 底 + 白字）。这一屏的彩色额度只有告警橙红一支，
而导航选中不是告警，所以它取交互冷色。

> 上一版是左侧 68px 图标轨，已在 A 版落地时整体退役。图标轨的问题不是难看，
> 而是七枚图标要求用户把中文标签记住才能定位；值班场景里人一进门就该看见
> 「告警事件」四个字，而不是先解码一个图标。

顶栏右侧留月度大屏入口与时钟。月度大屏走 `meta.fullscreen` 脱壳分支，不渲染顶栏
——墙上的屏不需要导航，也没有人在两米外用鼠标。

### 全站圆润是有代价的自觉选择

内容区一律直角、圆角只作为控件属性，本来是这一套的纪律；A 版把它放弃了，
理由是用户点名要「像现代 SaaS」。辨识度因此不再由形状
承担，改由**字号层级、数字排版和那支交互冷色**撑住——字号跨 0.6875rem 到 5.25rem，
比例字形与等宽分用。往结构与排版加力比往圆角加力有效。

`--signal` 这支冷色是相对上一版**新增**的第二支彩色。两支色的额度分工写死在
`tokens.css` 头部注释里：橙红只表示「确实有火 / 确实有告警 / 出错了」，冷色只表示
交互与选中。烟雾色 `--cls-smoke` 仍是中性深灰——红绿色盲下主要靠明度区分，
这条不许因为「看起来太素」而改。

### 识别框由前端画

`InferResult` 同时带 `detections[].xyxy`、`width` / `height` 与后端烧好的
`annotated` 位图。前端默认走 **`<DetectionOverlay />`**：一张原图加一层绝对定位
的 SVG，用 `viewBox="0 0 width height"` + `preserveAspectRatio="none"` 铺满——
图是 `width:100%; height:auto` 渲染的，显示长宽比与原图一致，于是 `xyxy` 就是
SVG 用户坐标，**不缩放就不需要任何换算**。

两处刻意的取舍：

- **线宽用 `vector-effect: non-scaling-stroke`**。否则 1920px 的图显示成 600px 时，
  2px 的框会缩成不到 1px 的发丝。
- **标签是 HTML 而不是 `<text>`**。SVG 的字号在用户坐标里同样会被缩放，1920px 图上
  的 12px 字只剩不到 4px 看不清；标签改成绝对定位的真实 px，位置仍按百分比挂在框的
  左上角。

`.pair` 的双栏对比已改为**图占主位 + 右栏 380px 账本**的单栏形态，但
`.fs-ledger` 的检测框账册保留，主位标题行多一组「叠加图 / 后端标注图」切换
——两套画法放在一起才看得出差异，而 `annotated` 仍是唯一能对照「后端到底在什么
尺寸上画的框」的凭据。账册行与 SVG 框双向 hover 联动：账册是密度的读法，
框是位置的事实，两边必须能互相指认。

两处为了可点而做的处理：

- **`rect` 用 `fill: transparent` 而不是 `fill: none`**。按 SVG 规范 `fill: none`
  的图元不参与命中测试，那样只有两三像素宽的框线可指，指着框中间反而没反应。
- **账册列出全部检出，不按置信度门槛过滤**。后端已按 `conf` 参数筛过一道，
  前端再藏一层等于凭空丢信息；复核时最该看的恰恰是低分的那些行。它们只压暗
  （`.is-weak`），并在账册标题旁报「低于 0.70 的 N 个已压暗」。

> 后端自研的 `BeautifyVisualizer` 仍只服务监控与平台推流那条链路；Web 识别页
> 一直用的是 ultralytics 的 `Results.plot()`。前端画框让识别页不必再依赖那份位图，
> 但没有改后端。

**Element Plus：用它的组件，换掉它的默认皮。**

EP 早就装在依赖里，`main.ts` 也早就在 `app.use(ElementPlus)`，那 361KB 的样式
一直躺在产物里——**却在 `src/` 下找不到一个 `<el-` 组件**。等于白付。后来决定
全面启用，但同时定下一条纪律：**启用组件 ≠ 保留默认外观**。

理由不是审美，是同源风险。EP 的默认皮正是它最强的识别特征，而参考项目
FireObserve 的历史页用的就是**原装** `el-table :border="true"` + `el-progress`。
照搬默认样式等于把两套界面拉回同一个模子。`styles/ep.css` 因此逐项拆掉：
表格的方卡与灰底、分页的蓝底蓝字、骨架屏的微光扫过、空状态的具象插画、
确认框的圆角阴影，全部换成账册表的语言。当前用上的是确认框
（`ElMessageBox`）、轻提示、骨架屏与空状态。

样式导入顺序是 `element-plus/dist/index.css` → `tokens.css` → `ep.css` →
`base.css`：令牌必须先到位，覆盖层才知道往哪接。

**表格不迁 el-table。** 这是评估后撤回的计划，撤回理由是硬的：

- **告警事件表不迁**。`/api/events` 只暴露 keyword/label/status/start/end/limit/offset，
  排序写死在 `alerting/store.py:196` 的 `ORDER BY ts DESC`；没有 sort 参数时，
  el-table 的列排序只会重排当前这一页的行，却长得像全局排序——比不排更误导。
  另外 el-table 的 `<tr>` 由组件内部生成，只接受 `rowClassName` / `rowStyle`，
  挂不上 `data-event-id`，而 `events.spec.ts` 正是靠这个属性定位行。
- **归档权重 / 对比评估 / 训练记录暂不迁**：这三张表同样没有后端排序，
  迁过去只买到分页控件，而分页逻辑本来就自写且与筛选状态耦合很深。

反过来的理由也成立：自研的 `.fs-ledger` 与 EP 的方卡**本来就差得更远**，
保持原样零风险。要迁时按上面 `ep.css` 的口径改即可。类别与状态标签仍用自研
`<span class="tag">`，不用 `el-tag`：标签的圆角 + 边框配方同属那套要避开的
识别特征。

浅色化之后这套形状语言**整块保留**——换的是明度关系，不是信息架构。
圆角从 3px 放到 6px，贴近现代后台的观感。

### 字体

- **Space Grotesk** —— 拉丁字母与数字的字形来源；**中文交给系统 CJK**
  （`PingFang SC` / `Microsoft YaHei`），不下载数 MB 字库
- **IBM Plex Mono** —— **只给数字**，且**凡是需要纵向对齐的数字都给**

关于等宽字体：它常被视作「AI 生成页面」的痕迹之一。这里使用它的理由是**仪表读数语义**——
数值需要对齐小数点、实时跳动时字宽不能抖。约束是只给数字、不给标签和正文。

反过来，**大号独立数字不用等宽**：等宽会让 `121` 在大字号下显得松散。
故头号风险读数用比例字形，读数条与表格用等宽。

**`CountUp` 的 `digits` 必须显式给。** 它默认 `0` 位，即 `toFixed(0)`——把 `0.991`
显示成 `1`、把误报率 `4.4%` 显示成 `4%`。这不是显示瑕疵，是**报错数**，比不显示
更难发现：读者不会怀疑一个看起来正常的整数。

### 动效：集中定义，逐处尊重降级

动效参数住在 `tokens.css`，缓动各有分工不可混用：`--ease` 用于原地状态变化
（悬停、底色），`--ease-out` 用于进场（起手快收尾稳），`--ease-back` 用于
「某件事刚发生」的回弹。时长按**元素离眼睛多远**分档，而不是按效果复杂不复杂：
`--dur-1` 150ms 是控件反馈，`--dur-2` 250ms 是块级转场，`--dur-3` 320ms 与
`--dur-4` 450ms 是整页级别的读数变化。超过 600ms 的等待动画在真实网络下显得卡。

三处动效各有各的规矩，**各自守各自的降级**：

| 动效 | 口径 | 降级怎么判 |
|---|---|---|
| 数字滚动 `<CountUp>` | 差值小于 `--count-min-delta`（2）不滚；时长随跨度增加但封顶在 `--dur-4`；滚动起点取「当前显示值」，被打断时从屏幕上看得到的位置接着走 | 自己判 `matchMedia` |
| 图表绘制 | 柱状图按 x 轴下标错峰 18ms 立起来；折线整条一起画完不逐点跳（连续量逐点跳会读成「在抖」）；时长 520/760ms | `EChart.vue` 自己判 |
| 进/出大屏 | 两套转场类跟着目标分支走，切换时新旧自动成对 | 全局 CSS 闸门 |

**降级不能只靠 CSS。** `base.css` 那条 `prefers-reduced-motion` 规则只压得住
CSS 动画与过渡，而 ECharts 画在 canvas 上、由 JS 驱动时间轴，`CountUp` 更是
自己 `requestAnimationFrame`——这三者都要各自判一次。漏判的后果不是「动得太多」，
而是「宣称支持降级但实际没降」。

配置构造函数（`charts/options.ts`）保持纯函数，**只描述数据长什么样，不描述它
怎么动**；动效由 `charts/motion.ts` 统一合成，`EChart.vue` 在 `setOption` 前过
一遍。理由：动效是跨页的一致性决策，写进 options 会散成六份互相矛盾的数字，
而且那份文件可以被单测直接调用，注入动效会让测试开始关心动画帧数。

### 页面布局：按操作频率分栏

每页的主次不由信息类型决定，由**使用频率**决定。低频的东西收进窄栏常驻，
高频的东西占主视区，不用滚。

| 页 | 左窄栏（低频） | 右主区（高频） |
|---|---|---|
| 实时监控 | 启动参数 320px | 状态条 + 画面 |
| 分析报告 | 历史报告 280px | 生成参数 + 正文 |
| 月度大屏 | —— | 五个读数（去卡片化，总量领读） |
| 识别检测 | 参数托盘（横贯顶部） | 图占主位 + 右栏 380px 读数与账本 |

窄屏（≤1100px）一律折回纵排。这是这轮重构里改动最小、收益最大的一条：
原先监控页三块全宽纵排，看一眼画面要滚过整张参数表；报告页的历史报告在页尾，
翻旧报告得先滚到最底。

宽账册（模型库的归档表 11 列，约 1200px 起步）外包 `.fs-scroll`。
否则一旦顶宽，出的是**整页**横向滚动条——会把顶栏一起拖走。

## 五、图表规范

后端返回聚合数据，前端负责呈现。两条硬约束：

### 1. 绝不做双 Y 轴

「告警次数」与「平均置信度」量纲不同。放在同一张图上做双轴，
两个刻度的对齐关系是任意的，会**凭空造出数据里没有的相关性**。

改为两张共用 X 轴的小倍数图：上图看次数，下图看置信度。

### 2. 时间序列必须连续

`/api/overview` 的 `daily` 恒定返回 `days` 项，无告警的日子补 0。

若只返回有数据的日期，坐标轴会把「空窗」画成正常间隔——那等于对读者说谎。

但**补 0 只适用于计数**。平均置信度在无样本时是**未定义**而非 0，
前端对其做断点处理；若填 0，折线会砸到谷底，读起来像「模型置信度为零」。

### 3. 其他

- 类别颜色按固定槽位分配，不随筛选后的排名变化，也不按数值深浅着色
- 网格线用实线细线（虚线会被误读成「阈值」或「预测」）
- 两个及以上序列必须有图例；单序列不要图例，标题即命名
- 不做两段式饼图，数字本身就是答案

**每个视图都必须有路由指向。** 曾经的 `PendingView.vue` 是一个「未建模块的
占位」通用件，长期没有任何路由指向它。它在 2026-10-09 的代码审查中被列为
死代码并删除——占位页应当由每个未建模块各自持有、由路由直接引用，而不是
一个没人指向的通用件。

**共用控件一律进 `base.css`，不进某个页面的 scoped 样式。**
`.fs-btn-ghost--tiny` 曾定义在告警事件页的 scoped 块里，而训练中心与模型库共
5 枚按钮在用它——scoped 编译成 `[data-v-事件页]` 限定，那些按钮拿不到规则，
高度悄悄退回标准按钮的 32px。不报错、不变红，只是矮了一截。

**同名类不做两套配方。** A 版在 `base.css` 新增了全局 `.pick`（胶囊）与 `.chip`
（状态胶囊），而训练中心的表格行内按钮叫 `.pick`（无边框文字按钮）、模型库的
勾选胶囊叫 `.chip`（描边）。同名不同配方必然漂移，训练中心那枚已改名为
`.runlink` 并注明理由；模型库那枚直接删掉自己的描边配方，继承全局胶囊——
后者没有测试依赖它的边框属性。**冲突时先看 e2e 有没有依赖，再决定改谁。**

**`api/types.ts` 与后端 `schemas.py` 必须同步修改。** 响应字段改名属破坏性变更。

### 画布与 CSS 变量的重复

ECharts 走 canvas，读不到 CSS 变量，因此 `charts/palette.ts` 必须镜像 `tokens.css` 的数值。

这是**必要且已知的重复**：改任一侧都要同步另一侧，并重跑第四节的配色校验。
文件内已标注。

## 七、无障碍与降级

| 项 | 做法 |
|---|---|
| 键盘焦点 | `:focus-visible` 用实线描边，不用光晕（浅色下用 `--ink` 近黑） |
| 降级动效 | 全局响应 `prefers-reduced-motion`，一并关闭过渡与动画；**ECharts 另判一次**，因为它画在 canvas 上、由 JS 驱动时间轴，CSS 那道闸门管不到它（`EChart.vue` 的 `apply()`） |
| 数字滚动 | `<CountUp>` 同样自己判一次 `prefers-reduced-motion`，直接落终值 |
| 加载态诚实 | 数据未到时读数显示「—」而非 `0`，面板给骨架屏而非「尚无」结论——`0` 与「尚无」都是在把「不知道」说成「没有」 |
| 色觉障碍 | 类别配色经 deutan / protan 模拟校验（ Machado 2009 severity 1.0）。白底下类别分离度：烟 vs 火 ΔE 32.1 / 45.7 / 50.2，烟 vs 交互色 29.6 / 27.4 / 29.5。**烟色不可改浅**，原因见第四节 |
| 对比度 | 正文 ≥ 4.5:1；图形标记 ≥ 3:1。白底实测：`--ink` 16.58:1、`--ink-body` 12.03:1、`--ink-mute` 4.62:1、`--alarm` 4.62:1、`--signal` 4.63:1、`--ink-faint` 3.22:1 |
| 空态 | 给出下一步动作（如「去做一次识别检测」），不是一句「暂无数据」 |

## 八、已知技术债

| 项 | 影响 | 计划 |
|---|---|---|
| ECharts 全量引入 | 单 chunk 约 1MB（gzip 346KB） | 改为按需引入 |
| 图表无数据表视图 | 无鼠标时读取数值不便 | 补表格切换 |
| `metrics.txt` 返回原始浮点串 | 前端需自行收窄位数 | 或改为后端返回数值 |
| 训练中心三段长面板之间零分隔 | 长页里找不清段落边界 | 待定 |
| 四张最密的账册表仍是手写 `<table>` | 无虚拟滚动、无列宽拖拽 | 后端加 sort 参数后再议（理由见第五节） |
| `.head__*` / `.tag` 仍在多页各写一份 scoped 配方 | 同类元素会各自演化 | 已把全局基类上提到 `base.css`；再出现第三处漂移就上提变体 |
