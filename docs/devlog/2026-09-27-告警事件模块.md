# 2026-09-27 · 告警事件模块（v1.5.0）

> 阶段：S5 · 产出：事件查询 REST 层 + 值班事件页
> 上一个模块见 [`2026-09-27-浅色主题与P0-1探针.md`](2026-09-27-浅色主题与P0-1探针.md)

---

## 起因

ROADMAP 的 P1 待办第一项：**告警事件**（事件筛选分页、片段回放、标记误报、导出 CSV）。
交接文档把它标为「工作量最小」——后端原语齐备（`EventService`、`EventStore`），只差
REST 层与页面。

实际做下来，**原语齐备只是指接口签名在**，下面压着三个真问题。这一篇主要记这三个。

---

## 一、先看数据模型，决定接口能做什么

`alerts` 表：`event_id`(PK) / `ts` / `frame_index` / `labels`(逗号连接) / `conf` /
`location` / `message` / `clip_path` / `is_false_positive`。

`EventStore.list_events(limit)` 只有 `ORDER BY ts DESC LIMIT ?`：**没有筛选、没有
offset、没有 count**。`EventService.list_events(keyword, label, limit)` 是「先取 N 条，
再在 Python 里过滤」。

这就是第一个问题。

### 问题一：筛选在 LIMIT 之后做，分页必然是错的

```
store.list_events(limit=200)      # 只取最近 200 条
  → Python 里再按 label / keyword 过滤
```

后果有三层，一层比一层隐蔽：

1. 筛一个稀有类别时，如果匹配都落在第 201 条之后，接口返回**空**——用户以为
   「这段时间没告警」，其实有。
2. 没法做分页：`offset` 无从下手（过滤后的行数不是从数据库来的）。
3. 没法算 `total`，而前端页码要靠它。

改法是把筛选下沉到 SQL。`EventStore._where()` 拼条件（全走占位符，不做字符串插值），
`query_events()` / `count_events()` 共用它。

**排序加第二键**：`ORDER BY ts DESC, event_id DESC`。`ts` 只到秒，一次推理在同一秒里
产生几十条是常态（实测 80 条里有大量同秒），没有稳定定序时分页会漂——第 1 页和第 2 页
出现同一条、或者某条两边都不出现。

## 二、`event_id` 是每次运行从 1 开始的计数器

准备演示数据时发现的。`AlertPolicy.fire()`：

```python
event_id=f"evt-{self._seq}"      # _seq 每次构造从 0 开始
```

而它是**事件库主键**，写入用 `INSERT OR REPLACE`，片段文件名也是 `{event_id}.mp4`。

**跑第二次推理，第一次的事件会被逐条改写**：`ts` 换成新时间、`conf`/`message` 覆盖、
片段文件同名被覆盖。事件历史被无声截断在一轮之内，而界面上看起来一切正常——
只是「总数没涨」。

这个 bug 从 S3 就存在，因为它需要**跑两次推理**才会显形。

改法：`AlertPolicy(..., id_prefix="")`，`run_inference` 传运行时间戳：

```python
run_stamp = datetime.now().strftime("%Y%m%d-%H%M%S")
AlertPolicy(cooldown_sec=..., location=..., id_prefix=f"{run_stamp}-")
```

默认空串保持原行为，`tests/test_09_alerting.py` 里断言 `evt-1` 的老用例不受影响。

**验证方式就是复现它**：连续跑两次推理，事件数 40 → **80**，来自 2 个不同前缀。
修复前会停在 40。

## 三、片段回放从上线起就是坏的（两处独立缺陷）

页面做完、截图一看，回放区是一块黑、只有一条控制栏。

### 3.1 编码浏览器不认

`write_clip` 用的是 `cv2.VideoWriter_fourcc(*"mp4v")`——MPEG-4 Part 2。而浏览器只认
H.264 / VP8 / VP9 / AV1。

本地探测**不足以判断**：`cv2.VideoCapture` 能正常回读 mp4v，一切「正常」。所以做了
一次浏览器实测，拿四种编码各写一份，让 Edge 去播：

| 编码 | readyState | 画面尺寸 | 结果 |
|---|---|---|---|
| VP90 / webm | 4 | 640×360 | ✅ |
| avc1 / H.264 | 4 | 640×360 | ✅ |
| AV01 | 4 | 640×360 | ✅ |
| **mp4v** | 0 | 0×0 | ❌ `DEMUXER_ERROR_NO_SUPPORTED_STREAMS` |

**结论：只测本地解码等于没测。** 播放能力是浏览器侧的事实，必须在浏览器里验。

### 3.2 `isOpened()` 撒谎，写出空容器也不报错

顺手测 H.264 时撞见的：

```
Failed to load OpenH264 library: openh264-2.5.0-win64.dll
[libopenh264] Unable to create encoder
[ERROR] Failed to initialize VideoWriter
```

同一段代码里 `writer.isOpened()` 返回 **`True`**，不抛异常，写出一个 **1001 字节**的
mp4——只有文件头，零帧。`write_clip` 会把这条路径记进数据库，界面给出「回放」按钮，
点了什么都没有。**这就是本项目最怕的那类缺陷：不报错、有产物、结果是空的。**

改法：`write_clip` 逐候选编码试写，**每个都回读帧数验证**：

```python
_CODECS = (("VP90", ".webm"), ("VP80", ".webm"), ("avc1", ".mp4"), ("AV01", ".mp4"))
```

- 返回**实际**落盘路径（后缀可能变），调用方不再自己拼 `.mp4`
- 全都不行就抛错、不记片段——界面显示「未留存」，比给一个假按钮诚实
- **`mp4v` 故意不作兜底**：能编出文件但没人能看，比没有文件更糟

顺带在页面上加了兜底：`<video>` 的 `error` 事件会显示「这个片段浏览器解不开」并给出
下载链接。历史片段（mp4v 那批）因此不会变成无解的黑屏。

## 四、页面本身

- 筛选栏：关键词 / 类别 / 状态 / 起止日期 / 每页 / 清空条件 / 导出 CSV
- 账册：时间 · 类别 · 置信度 · 消息 · 片段 · 状态 · 操作
- 明火用 `--alarm`（这是它该出现的地方），烟雾用中性色；已标误报的行压暗
- 类别中文名从 `/api/system/status` 取，不在前端再抄一份契约
- 空态区分「一条都没有」与「当前筛选没匹配」——前者提示去跑 `fs-infer`

### 参数校验：拒绝而不是安静地返回空

`label=flame`（拼错）如果不校验，会返回 0 条。用户看到的是「这段时间没有告警」，
而事实是参数写错了。所以 `label` / `status` 传未知值一律 **400** 并说明可接受值。

## 五、我自己踩的坑

### 5.1 用 PowerShell 做源码文本替换，造出一个无限递归

要把 E2E 里的 `page.goto('/events')` 批量换成 `openEvents(page)`：

```powershell
(Get-Content f) -replace "await page\.goto\('/events'\)", "await openEvents(page)" | Set-Content f
```

替换把 `openEvents` **函数体内部**那行也换了，于是函数调用自己。交接文档明确写着
「用 Edit 工具改文件，别用 PowerShell」——那条纪律正是为这种情况写的，我还是犯了。

### 5.2 E2E 被「瞬时状态」骗过：5 个用例静默跳过

`/events` 挂载后、首次请求返回前，页面渲染的**正好是空态**。我的「等账册或空态出现」
辅助函数于是立刻通过，接着读「事件 N 条」读到初始的 0 —— 5 个依赖数据的用例全部
`test.skip`，报告上是「跳过」，看着不像失败。

改法：页面暴露 `data-loaded`，测试等它变 true。**「等某个元素出现」不等于「等数据到达」**，
两者之间隔着一次异步请求。

### 5.3 分页按钮点了不生效

`offset` 是个普通 ref，我 watch 了 `filters` 和 `pageSize`，**没 watch `offset`** ——
改 offset 不会重新取数。E2E 的分页用例直接抓到了（「第一行的 id 没变」）。

没有给 offset 加 watcher（那会让「筛选重置 offset」连带触发两次请求），而是让翻页走
一个 `goTo()` 函数。

### 5.4 构建失败但 E2E 照样「跑过」

改完分页我改了 `load()` 的签名，漏改 `onMounted` 里的一处调用 → `vue-tsc` 报错、
**构建失败**，但 `npm run build` 的输出被我 `Select-String 'error|✓ built'` 过滤后只看了
一行，没注意；E2E 于是跑在**旧产物**上，失败得莫名其妙。

**构建失败时必须先看构建，E2E 的结果没有意义。**
