## 一、起因：跑完一次实验就会悄悄换掉线上模型

交接文档把模型库列为 P1 剩项，功能是「设为当前、下载权重、多权重对比」。
但真正动手时，第一件事不是写页面——是发现**「设为当前」这个需求本身就暴露了一个正在发生的问题**。

`deps.active_run()` 原来的实现：

```python
def active_run() -> Optional[ArchivedRun]:
    """当前权重：取最新一个归档。前端「设为当前」后续接入显式选择。"""
    runs = archived_runs()
    return runs[0] if runs else None
```

「当前权重」=「最新归档」。而归档发生在**每次训练结束**时。于是：

> 17:15 用户自己起了服务，17:16 从界面发起一次 30 轮、`imgsz=512` 的训练，
> 17:49 训练完成并归档（mAP50 **0.7432**）。于是识别页从那一刻起用的就是这份新权重，
> 而它比原来那份（0.7675）**更差**——页面上没有任何提示。

这不是「一个小设计取舍」，而是把「跑了一次实验」等同于「换掉生产模型」。
**每一次实验都会自动上线**，而实验的目的恰恰是「看看它行不行」。

所以「设为当前」不是一个锦上添花的功能，它是这个 bug 的修复。

### 状态机

状态放在 `models/active.json`（gitignore）。为什么不入库：它描述的是**本机哪一份本地归档**
生效，而归档本身不入库（5 MB 级权重），提交指针只会在别的机器上指向不存在的文件。

解析结果带 `source` 与 `note`，因为「没指定过」和「指定的被删了」对用户是两件事：

| `source` | 含义 | note |
|---|---|---|
| `pinned` | 用户指定，且存在 | 空 |
| `fallback-newest` | 从没指定过 | 「没有指定过当前权重，按最新归档取」 |
| `fallback-missing` | 指定的已被删 | 「指定的 xxx 已不在归档里（可能被删），暂用最新归档」 |
| `none` | 没有任何归档 | 「还没有任何归档训练」 |

**静默回落是这里最容易犯的错**：用户明明设过，某天发现「当前」变成了别的，
却没有任何解释。所以 `note` 是接口的一部分，不是可选的装饰。

`ActiveModelStore.resolve(available)` 把「扫目录」留在外面：目录扫描那一套
（两种归档布局，见 `archived_runs` 的注释）归 `deps`，状态归 service。这样状态机可以
单独测，四种来源一个用例一条。

## 二、对比评估：为什么是后台任务 + 轮询

`evaluate_weights` 早就有（`fire_sight_platform.evaluation.service`），
`compare_runs` 也是现成的。缺的只是让界面能调。

先算成本：val split 是 1722 张图。同步 POST 跑两个模型要一分多钟，
**前端会先超时**，而且中途没有任何反馈——用户看到的只是一个卡住的按钮。
所以走后台任务。

**为什么不用 SSE**（训练用的是 SSE）：
训练进度是**逐轮**的、要画实时曲线，SSE 的实时性是必需的。对比评估的进度粒度是
**逐个模型**（几十秒一个），隔两秒轮询一次完全够用，而且不必占一条长连接。
训练那套 SSE 的坑（事件必须带 `type`，漏了就静默丢事件）在这里没有回报。

**GPU 互斥**：起任务前先抢 `GPU_LOCK`，抢不到立刻抛 `GpuBusy` → 409。
如果放在线程里抢，用户会看到一个「已发起但马上失败」的任务，比直接 409 差。
抢到之后如果线程起不来，锁必须还回去——否则这台机器再也起不了训练或评估。

### 结果行的键集合必须固定

第一版每个结果行是就地拼的 dict：成功时有 `mAP50` 没有 `error`，失败时有 `error`
没有 `mAP50`。写测试时 `first["error"]` 直接 `KeyError`。

**形状随结果变化，前端就得给每个字段写两套分支**，而漏键的后果是渲染崩掉，
不是显示一个「—」。改成 `result_row()` 统一给全字段。

（顺带排除了一个误判：我一开始以为 FastAPI 把 `None` 字段丢了，
写了个最小复现才发现它不丢——**是我的测试读的是内部字典而不是接口响应**。
先复现再下结论，省下了一次错误的「修复」。）

## 三、实测：那次 30 轮实验值不值

模块做完直接真跑了一次（不是 mock），两个模型 **60 秒**：

| 模型 | mAP@50 | mAP@50-95 | 精确率 | 召回率 | 烟雾 / 明火 (m95) |
|---|---|---|---|---|---|
| 30 轮 / imgsz=512 | 0.7385 | 0.4097 | 0.738 | 0.674 | 0.459 / 0.360 |
| **50 轮 / imgsz=480** | **0.7651** | **0.4420** | **0.781** | **0.702** | **0.520** / 0.364 |

**30 轮那次在每一项上都更差。** 有意思的是差距几乎全在烟雾（0.459 vs 0.520），
明火几乎持平（0.360 vs 0.364）——轮数不足对「烟」这种弱纹理、边界模糊的目标影响更大，
这和 P0-1 探针里“fire 的中位框只占画面 7.1%”是两回事：明火框小但纹理强，
反而更容易在小轮数下学到。

### 一个必须说清的差异

评估用 `imgsz=640`，而两个模型分别是在 512 / 480 下训练的。所以这里的
0.7385 与归档里 `metrics.txt` 的 0.7432 **不一样**。

这不是算错了：**对比的意义是让所有模型站在同一条起跑线上**（同样的推理分辨率、
同样的阈值口径），而不是复现各自的归档数字。界面上把 imgsz 与口径都写了出来，
免得有人看到对不上就以为评估有问题。

## 四、这一轮我踩的坑

### 4.1 又犯了一遍「等数据到达」的错

`ModelsView` 里我写了 `:data-loaded="!busy"`。挂载时 `busy` 是 false，
所以这个属性**一开始就是 true**，E2E 的等待形同虚设；页面此时正好渲染空态，
于是 6 个用例全部 `skip`，报告上只显示「6 skipped」，看着像正常的按需跳过。

告警事件页（v1.5.0）明明踩过同一个坑并记进了 devlog，这次还是犯了。
改法是专用的 `loaded` ref，在 `finally` 里置位。

**光是记下来不够，所以这次连同「跳过判据」一起改了**：E2E 判断「要不要跳过」
不再数页面上的行数，而是**问后端**（`GET /api/models`）。这样「页面渲染坏了」
会变成**失败**而不是跳过——前者会有人去修，后者不会。

### 4.2 选择器太宽，测出了错误的东西

页面上有**两张** `.fs-ledger`：归档表与对比结果表（视图在挂载时会接回最近一次任务，
所以真跑过一次对比之后，结果表一直在）。于是：

```
page.locator('table.fs-ledger tbody tr')      → 期望 3 行，实际 5 行
page.locator('... td.is-num')                 → 把「0.459 / 0.360」当成非法数值
```

这两条是*加了一张表之后*才失败的——**测试写的时候页面只有一张表**。
现在两张表各带 `data-table="archives"` / `data-table="eval"`，选择器显式限定。

教训：**表格类断言不要用「页面上所有同类元素」这种选择器**，多一张表就串了。

### 4.3 替换编辑把表头删掉了

我用 Edit 工具时把 `old_string` 从 `<table class="fs-ledger">` 一直划到
`<th class="is-pick"></th>`，替换成只带新属性的 `<table>` —— 于是 `<thead><tr>` 和
那个 `th` 一起没了。构建不报错（模板语法没坏），是 E2E 的表头断言会挂。

**替换的边界要贴着想改的那一行**，不要顺手把后面的结构一起框进去。

### 4.4 端口 8000 上跑的是用户自己的服务

我照例重启服务后 `pwsh-14` 起不来（WinError 10048 地址占用）。
查下去发现占用者是 17:15 启动的一对 python 进程，**父进程是 explorer 启动的
powershell.exe**——是用户自己开的窗口，不是我 job 的进程树。

这次我没有像之前那样直接杀掉：那是用户的进程。改成先确认它已退出（用户后来关掉了），
再照常起托管服务。**「我之前几次重启都是杀掉端口占用者」不是继续这么做的理由**，
要看清楚那个进程是谁的。

（另外这也解释了 4.1 里那次 17:16 的训练：用户在自己起的服务上点了开始训练。）

## 六、遗留

- **对比评估的图件会被互相覆盖**。`evaluate_weights` 内部用
  `name=Path(weights).stem` 作为输出目录名，而从归档来的权重**都叫 `best.pt`**，
  于是每个模型的评估图件都落到 `.runtime/evaluation/best/` 并互相覆盖。
  目前没有消费方（结果从返回值读），所以不影响数字；但将来要做「对比图件」就得先修。
- 任务表在内存里，服务重启即清空（与训练任务一致）。界面挂载时会接回最近一次任务，
  但重启后就没了——**这是刻意的**，落盘任务表要先想清楚过期与清理策略。
- 评估固定跑 `val` split，不可选；`test` split 要选的话得先想清楚「拿测试集反复比较」
  这件事本身合不合适。
