# docs/ —— 项目文档

文档与代码同步变更。**改代码时顺手改对应的文档**，不要留到「以后统一补」。

## 目录

| 目录 | 内容 | 什么时候看 |
|---|---|---|
| [`architecture/`](architecture/) | 架构决策记录（ADR），记录「为什么这么选」 | 想知道某个设计取舍的来由 |
| [`tech/`](tech/) | 各阶段技术设计与实现说明 | 要改某个模块的实现 |
| [`api/`](api/) | CLI 命令与 REST 接口说明 | 要调用某条命令或接口 |
| [`wiki/`](wiki/) | Code Wiki：架构、模块职责、关键类与函数、依赖关系、运行方式 | 想从代码视角通读全仓、上手或评审 |
| [`devlog/`](devlog/) | 按阶段/日期记录的开发日志 | 想了解某段时间做了什么、踩了什么坑 |
| [`reviews/`](reviews/) | 代码审查报告（`YYYY-MM-DD-<主题>.md`） | 想知道某次审查发现了什么、修了没有 |
| [`superpowers/`](superpowers/) | 新子系统的设计规格与实现计划（spec / plan） | 想知道某个功能当初是怎么设计与拆解的 |
| [`assets/`](assets/) | README 等文档引用的图片 | — |
| [`ROADMAP.md`](ROADMAP.md) | 阶段路线图与完成情况 | 想知道现在到哪一步了 |

## 约定

1. **`references/` 不入库**。对齐参考文档后得出的结论写进 `docs/`，原始 PDF 与参考资料留在本地。
2. **阶段文档用 `S<序号>` 前缀**（`S1-`、`S2-`…），与 `ROADMAP.md` 的阶段划分对应。
3. **开发日志按日期命名**：`YYYY-MM-DD-S<序号>.md`。
4. **REST 接口文档**（[`api/REST-API.md`](api/REST-API.md)）是前端与后端的共同契约，
   改动接口必须同时更新该文件与前端 `apps/web/src/api/types.ts`。

## 新增文档

- 新的设计说明 → 放 `tech/`，文件名 `S<序号>-<主题>.md`
- 新的接口说明 → 放 `api/`，文件名 `<主题>.md`
- 一次重要的技术取舍 → 放 `architecture/`，文件名 `ADR-<三位序号>-<主题>.md`
- 一段开发过程 → 放 `devlog/`，文件名 `YYYY-MM-DD-S<序号>.md`

新增后回到本文件，在对应表格中补一行。
