# 测试说明

本文说明仓库内全部自动化测试的**用途、如何运行、结果在哪里看、预期是什么**。

命名约定：`test_<序号>_<模块名>.py`，序号即推荐执行顺序（工程骨架 → 数据 → 训练 → 推理告警 → 接口）。

```bash
pytest tests apps/platform/tests -q        # 全部，预期 327 passed
```

## 前端端到端测试（Playwright）

`pytest` 覆盖不到界面。`apps/web/e2e/` 下的 Playwright 用例驱动**系统已装的 Edge**
（不下载自带浏览器）跑真实交互。

前置：先起后端（`fs-serve`）并构建前端（`npm run build`）。刻意不配 `webServer`
自动起服务——本项目连的是真实工作区与真实模型，自动起的服务容易让人忘了它在动真数据。

```powershell
cd apps/web
npm run test:e2e            # 默认套件，约 50 秒，无副作用
npm run test:e2e:ui         # 带界面，便于调试
```

实测：**37 passed / 6 skipped**。6 条跳过都是按需跳过，不是渲染坏了 ——
「全 skip 看着正常、实际是页面坏了」正是 `models.spec.ts` 里记过的坑，
所以这里写明每条为什么跳：

| 跳过的用例 | 条件 |
|---|---|
| `training.spec.ts` 启动训练 | 需 `FIRESIGHT_E2E_TRAIN=1`，会真的跑一次训练 |
| `report.spec.ts` 生成冒烟 | 需 `FIRESIGHT_LLM_API_KEY`，真调大模型（花钱） |
| `resume.spec.ts` ×3 | 需存在**未跑完且优化器状态还在**的现场 |
| `models.spec.ts` 无归档时的空态 | 需 `models/trained/` 为空 |

`resume.spec.ts` 那 3 条自数据集换代起一直是跳过的：唯一一份可续训现场
（`20260927-104246-D-Fire-train-yolo11n`，停在第 5 轮）已随 `D-Fire/train` 归档
一并删除。要验续训链路，先新起一次训练并在中途停掉。

| 用例 | 覆盖 |
|---|---|
| `smoke.spec.ts` | 页面能打开、后端数据能读到 |
| `detect.spec.ts` | **上传图片→出结果**（文件选择框无法用截图验证）、账册表头与数字列对齐、结果图不拉伸、窄屏不塌 |
| `training.spec.ts` | 启动训练→实时曲线逐轮长出→结束归档；**默认跳过**，见下 |
| `report.spec.ts` | 分析报告页结构（时间选择 / 生成按钮 / 历史区）、区间无事件的拒绝提示；真调模型的生成冒烟**默认跳过**（需 `FIRESIGHT_LLM_API_KEY`，见下） |

### 关于会写数据的那条

`training.spec.ts` 里真正起训练的那条**会写出 `runs/` 与 `models/trained/` 产物**，
所以默认跳过，需显式开启：

```powershell
$env:FIRESIGHT_E2E_TRAIN="1"; npm run test:e2e
```

它自己负责清理产物。用 `demo_fire` + `epochs=2` + `fraction=0.2` + `imgsz=320`，
约 10 秒跑完。

> **别用大配置跑这条**：下拉默认选中的是列表第一个数据集（`D-Fire/raw`，14122 张），
> 在 CPU 上跑 0.2 的比例也要几十分钟。用例里已显式选 `demo_fire`。

### 关于真调模型的那条

`report.spec.ts` 的生成冒烟会**真的调一次大模型**（花真钱），所以默认跳过，
配了 `FIRESIGHT_LLM_API_KEY` 才跑：

```powershell
$env:FIRESIGHT_LLM_API_KEY="sk-..."; npm run test:e2e
```

只配了 `DEEPSEEK_API_KEY` / `SILICONFLOW_API_KEY` 不够——跳过门槛认的
**只有** `FIRESIGHT_LLM_API_KEY` 这一个名字。生成要几十秒，冒烟用例里用
`test.setTimeout(120_000)` 把**整条用例**的预算提到 120 秒：Playwright 配置的
默认 60 秒会先掐掉整条用例，只给 `expect` 更大的 timeout 没用。

## 不在自动化范围内

以下需人工执行，不作为 CI 门禁：

| 项 | 怎么做 | 看什么 |
|---|---|---|
| 完整训练 | `fs-train --dataset "D-Fire/raw" --epochs 50 --device 0` | 终端逐轮 loss / mAP；结束后 `models/trained/<run_id>/` |
| 网页启动训练 | 训练中心 → 启动训练 → 小配置（`fraction=0.2, epochs=3, imgsz=320`） | 实时曲线逐轮长出、日志滚动、结束后自动归档并出现在训练记录里；训练期间 GPU 锁生效（识别页返回 409） |
| 模型评估 | `fs-val --dataset "D-Fire/raw" --weights ...` | mAP@50、per-class AP、速度三段 |
| 视频回放验收 | `fs-infer --source <视频>` 后查看事件与片段 | 告警是否触发、片段可否播放、中文标签是否乱码 |
| 前端构建 | `cd apps/web && npm run build` | `vue-tsc` 类型检查 + 构建产物 |
| 界面冒烟 | `fs-serve` 后打开浏览器 | 风险尺、图表、空态是否正常 |
