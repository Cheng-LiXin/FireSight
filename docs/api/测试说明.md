# 测试说明

本文说明仓库内全部自动化测试的**用途、如何运行、结果在哪里看、预期是什么**。

命名约定：`test_<序号>_<模块名>.py`，序号即推荐执行顺序（工程骨架 → 数据 → 训练 → 推理告警 → 接口）。

```bash
pytest tests apps/platform/tests -q        # 全部，预期 67 passed
```

## 如何查看结果

### 终端（最快）

```powershell
.venv\Scripts\Activate.ps1

pytest tests apps/platform/tests -v                 # 全部
pytest tests/test_15_api.py -v                      # 只跑某一序号
pytest tests apps/platform/tests -q --no-header     # 精简输出
```

- 行尾 `PASSED` / `FAILED` / `SKIPPED`
- 汇总行形如：`67 passed in 7.15s`

### 保存到文件（便于留档）

```powershell
pytest tests apps/platform/tests -v --tb=short > test_report.txt 2>&1
```

### 算覆盖率（可选，需 `pytest-cov`）

```powershell
pytest tests apps/platform/tests `
  --cov=fire_sight_platform --cov=fire_sight `
  --cov=frame_source --cov=visualization --cov-report=term
```

## 不在自动化范围内

以下需人工执行，不作为 CI 门禁：

| 项 | 怎么做 | 看什么 |
|---|---|---|
| 完整训练 | `fs-train --dataset "D-Fire/train" --epochs 50 --device 0` | 终端逐轮 loss / mAP；结束后 `models/trained/<run_id>/` |
| 模型评估 | `fs-val --dataset "D-Fire/train" --weights ...` | mAP@50、per-class AP、速度三段 |
| 视频回放验收 | `fs-infer --source <视频>` 后查看事件与片段 | 告警是否触发、片段可否播放、中文标签是否乱码 |
| 前端构建 | `cd apps/web && npm run build` | `vue-tsc` 类型检查 + 构建产物 |
| 界面冒烟 | `fs-serve` 后打开浏览器 | 风险尺、图表、空态是否正常 |
